# 官方 dsh-pet 桥接迁移设计

日期：2026-10-20

状态：按用户后续明确要求，已直接移除内置 pet，正式入口只使用外置官方桥接。以下原始分阶段门禁记录作为设计历史保留；“先通过运动门禁才删除”已由用户后续指令取代，不代表运动精度已通过验收。

## 1. 目标与已批准边界

目标是从 Wallpaper 的源码部署、运行依赖和发布集合中移除内置派生桌宠 `dsh-we-pet-builtin`，改用用户安装的官方 `dsh-pet`。Wallpaper 只保留联动桥接、专属动画和配图，不复制官方桌宠的基础资源、渲染器或 Electron 运行部分。

用户已接受同一宠物在多个页面或 `display=both` 两端同步播放，不再要求动作只作用于发起页面。仍须保证多只宠物存在时目标明确、流程不串、失败可取消。多页面接收同一指令不等于允许多个页面重复下发整套演出。

已批准方向：官方接口驱动宠物；桥接自绘联动气泡。最初要求先验收关键位移再删除内置，用户随后明确改为直接删除内置、只保留官方桥接。仍须如实记录原生运动差异和未完成的真机验收。

## 2. 事实基线

官方源码审计基线：`PC2005-cloud/dsh-pet@7440b963ab7fb962cb7694e094aa0c9c7a438a7b`。

- [官方回复](https://github.com/PC2005-cloud/dsh-pet/issues/122#issuecomment-6284895356) 明确：控制指令共享后端状态；`surface` 只校验显示端，不负责隔离页面或两端。
- [官方 Cordis 契约](https://github.com/PC2005-cloud/dsh-pet/blob/7440b963ab7fb962cb7694e094aa0c9c7a438a7b/CORDIS.md) 提供同页 `petApi7340.pose(petId)` 与 `progress(petId)`，后者包含播放编号、实际播放时间、时长、暂停和缓冲状态。
- [官方 HTTP 契约](https://github.com/PC2005-cloud/dsh-pet/blob/7440b963ab7fb962cb7694e094aa0c9c7a438a7b/API.md) 提供 URL 动画、朝向、位置、原生抛掷、占用与释放。
- 官方锁按宠物 ID 隔离；携带失效锁编号的动作、续期会失败。用户点击或拖拽可以撤销第三方占用。
- 官方位置指令支持直接、弹簧和直线移动；尚无供第三方使用的本地逐帧位置写接口。
- 注册表当前版本号为 `0.3.7`。版本号查询不证明注册表产物包含上述全部接口，不能只用 `>=0.3.7` 判定兼容。
- 本仓当前固定检查内置身份、预构建指纹、私有控制面和九个动作注册。替换不是简单修改包名。

此前已运行官方位置、进度、锁和显示端校验的 44 项单元测试，全部通过。这不是本设计的端到端验收结果。

## 3. 方案取舍

采用「官方控制接口 + 桥接自绘气泡」，不采用以下路径：

| 路径 | 不采用的原因 |
| --- | --- |
| 继续携带派生 pet，只隐藏安装入口 | 不能降低包体积，仍需跟踪官方实现 |
| 给用户已安装的官方文件打补丁 | 更新会覆盖补丁，失败可能损坏用户安装 |
| 通过 React 私有字段、全局选择器或 DOM 顺序接管宠物 | 无稳定实例身份，多宠物时可能操作错误目标 |
| 保留官方原生气泡槽，再模拟两把锁 | 官方没有独立占用及气泡所有权契约，无法可靠隔离清理 |

桥接只创建自己的 DOM，不改官方源码、配置池和数据目录。侧栏与吉祥物仍由 Wallpaper 自己控制。

## 4. 组件职责

### 4.1 官方能力适配

在 pet-link 内建立小型适配层，保持现有主包门面的调用方式。适配层负责：

- 从同页 Cordis 生命周期取得位置和进度服务，不依赖 `window.__dshWePetCtl`。
- 显式传递目标 `petId`、`surface` 和本轮锁编号；动作通过受控素材 URL 点播。
- 记录并核对返回的 `playbackId`，以本页实际进度驱动侧栏和吉祥物效果。
- 映射官方错误为可诊断的不可用、忙碌、取消或播放失败，不把 HTTP 200 当作动作成功。
- 未发现目标或能力不足时停用联动，保留壁纸、设置和吉祥物原生回退。

目标 ID 默认沿用 `main`。在现有联动设置中提供一个目标选择控件，读取官方宠物列表、展示名称与 ID，选择仅写入 Wallpaper 设置，不改官方配置。内部状态以显式 `petId` 为键；不自动控制所有宠物，不自动回退到第一只宠物。没有匹配目标时保留选择并显示不可用状态，不新增多目标编排界面。

### 4.2 执行协调

在现有 pet-link 宿主组件生命周期内增加按目标的运行协调器。协调器不能成为新的独立安装包。

- 每轮包含宿主代次、页面标识、目标 ID、运行 ID 与官方锁凭证。
- 同一宿主、同一目标只有一条有效指令流。第二个页面或重复触发收到忙碌结果，不重复点播，也不强制抢锁。
- 不同目标使用独立状态，能够并行；锁丢失、到期、页面离开或组件卸载后结束对应运行。
- 页面存活续期与官方占用续期联动。失联后停止发新命令，不凭旧运行 ID 续上新一轮。
- 清理必须核对代次、运行 ID 和锁凭证；旧清理不得释放新运行或其他插件的锁。
- 只访问当前宿主的官方路由，不接收调用方指定的任意上游地址，避免引入任意 URL 代理。

官方锁处理与其他消费者的互斥；桥接协调器处理本插件多页面的重复触发。不能只依赖页面内变量或 `localStorage` 互斥。

### 4.3 自绘气泡

保留现有气泡编排、文案、配图和调参语义，替换显示后端。

- 气泡挂在桥接自有容器，按 `petId + runId` 管理；通过同页位置服务和成品配置中的尺寸确定锚点。
- 每轮拥有自己的 DOM、计时器与帧任务；关闭仅移除该轮节点，不调用官方 `bubble/clear`。
- 动作结束后释放官方锁，气泡可继续显示；气泡先结束时也不影响仍在进行的动作。
- 暂停或缓冲时，动作节点跟随实际播放进度，而不是只按墙上时钟推进。
- 目标消失、被用户接管、组件关闭时立即结束当前轮，并回收自有气泡和异步任务。
- 只用安全文本和受控资源地址渲染，不将接口返回字符串直接拼进 HTML。

明确接受的差异：官方锁释放后，原生气泡可能恢复显示。桥接避免遮挡和阻塞交互，但不承诺继续独占官方气泡槽，也不全局隐藏其他宠物的气泡。

气泡只属于发起联动且加载 Wallpaper 桥接的网页。其他网页可接收到官方同步动作，但不重复绘制本轮气泡、不重复下发演出命令。发起页面关闭时终止该轮。允许桌面宠物同步动作，不表示会向官方独立桌面窗口注入自绘气泡。

### 4.4 动作、位置与播放时钟

普通走位优先使用官方直线或弹簧位置指令，抛掷使用官方原生驱动。朝向随官方动画指令显式传入。专属动作直接使用 Wallpaper 素材 URL，不向用户动画池安装扩展。

严格同步部分单独验证：侧栏拉拽贴边、吉祥物抓取与下落、踢腿弹飞落地、哈气与侧栏展开。使用本页 `progress(petId)` 并核对本轮 `playbackId`，不能用其他页面的共享播放结束回执提前推进。

不得通过每帧 HTTP 请求模拟本地逐帧控制。若官方接口不能保留关键视觉关系，迁移在此门禁停止，向用户报告具体差异；不擅自删减演出，不重新引入派生 pet，不用脆弱的 DOM 定位掩盖问题。优先协调一个最小的官方本地运动扩展点。

## 5. 兼容与失败规则

- 不自动安装、更新、卸载或修改用户的官方 pet。
- 官方 pet 缺席时主功能照常，联动返回明确不可用原因。
- 能力检查同时覆盖客户端服务、目标存在及官方动作响应；正式演出前取得占用后再执行命令。
- 不为兼容探测播放测试动作，不为检测接口而改用户配置。
- 不能只因包版本符合就声称支持。未识别的旧接口、错误响应和缺失进度必须安全退出。
- 有锁却未真正播放、播放加载失败、用户接管、目标删除都要有超时或取消路径；不得永久停在最后一帧。
- 同 ID 替换缺少官方实例代次保证，因此不宣称严格实例隔离。观察到服务、目标或播放不连续时取消，不自动接续到另一实例。

## 6. 素材与体积

桥接保留演出必须的九段专属动画和配图，并通过自身固定资源路由提供；路由由白名单映射文件，不把调用方路径直接连接到磁盘。

删除对象是官方基础代码、基础动作与运行资源的重复副本，不是专属联动素材。本次不同时引入远程素材下载器或 CDN。

体积验收分别记录源码文件树、主包、桥接包和完整发布集合的文件清单与实际字节数。不能只证明根包不含 pet，却仍把 pet tgz 放进发布集合。

## 7. 实施顺序与验收

### 阶段一：官方适配与目标协调

先补失败回归，再实现适配。内置路径此时仍保留，但不允许单轮混用两种 provider。

验收：

1. 目标存在且有多个宠物时，只有请求 ID 收到命令；目标缺失不回退。
2. 两页面对同一目标触发，只产生一条有效演出流；不同目标可并行。
3. 所有动作、位置和抛掷均带正确目标与本轮锁；锁丢失后停止发命令。
4. 客户端服务缺失、旧官方版本、HTTP 200 且 `ok:false`、加载失败均安全退出。
5. 旧页面、旧运行和旧清理不能继续写入或释放新运行。

### 阶段二：自绘气泡与演出同步

验收：

1. 动作释放后，自绘气泡仍按本轮配置保留并到时回收。
2. 气泡先关闭不取消动作；旧气泡定时器不会关闭新气泡。
3. 原生气泡及其他宠物不受桥接清理影响。
4. 桌面、窄屏、缩放和两个宠物重叠场景不依赖 DOM 顺序识别目标。
5. 真浏览器验证四条既有演出，包含慢加载、缓冲、取消和用户拖拽；关键节点以实际视频时钟同步。
6. 关键位移的验收记录必须包含逐帧时间、宠物位置、目标边缘位置和截图；仅测试接口返回成功不算通过。指定贴边阶段的最大位置偏差不超过 4 CSS px，动作与侧栏关键节点时差不超过 80 ms；若已有场景的验收更严格，保留更严格标准。不得新增明显跳位或错误穿插。保持既有调参语义，达不到标准时停止移除内置路径，不自行放宽阈值。

### 阶段三：移除内置与部署回归

前两阶段通过后，才从被跟踪源码和安装、打包路径移除 `packages/pet`、派生包依赖、主 patch 行、预构建登记及旧内置控制面。清理时保留归属与许可证要求，不误删用户目录或用户安装。

同步修改源码安装器、发布集生成、锁文件、构建器、包形态守卫、部署夹具与中英文安装说明。通过动态发现计算包集合，不用放宽守卫跳过不存在的依赖。

已有 profile 中旧派生依赖的移除必须显式执行并先备份；不在插件启动时改 profile，不删旧桌宠用户数据，不卸载官方 pet。旧工具若不再适用，应明确报退役错误，不留下会修改官方文件的安装入口。

验收：

1. 干净源码检出和完整发布集合都不包含派生 pet，锁文件、依赖和 patch 无活动引用。
2. 未安装官方 pet 时，主包可安装启动，壁纸和吉祥物原生行为正常。
3. 安装兼容官方 pet 后，真实隔离 profile 中联动可用；更新、重装后保持同样结果。
4. 旧内置版到新官方桥接版的迁移不生成双宠物行，不覆盖官方配置或删除用户数据。
5. 静态检查、部署专项、组件生命周期与包纯度守卫通过；全链环境失败按实际情况记录，不冒充通过。
6. 不发布 npm、不推送远端、不操作活动 profile。此类操作另按用户授权执行。

## 8. 主要修改范围

- `packages/pet-link/lib/`：官方资格检查、宿主协调、受控素材路由，移除默认向内置数据根的 provisioning。
- `packages/pet-link/src/`：官方适配、自绘气泡、演出状态机与现有调参面衔接。
- `packages/pet-link/tools/`：审查并退役外部文件补丁及旧资源注入入口。
- `scripts/build-client.mjs`、部署与发布脚本：移除预构建 pet 处理，保留真实依赖闭包。
- 根清单、锁文件、`cordis.patch.yml`、包形态登记及受影响测试：删除派生身份的活动依赖；不放宽其余子包契约。
- 相关安装、升级与联动说明：明确外置官方依赖、能力要求、同步播放范围和自绘气泡边界。

## 9. 完成定义

只有「官方真实接入 + 多目标与多页面协调 + 独立气泡生命周期 + 关键演出视觉验收 + 两通道无内置部署」全部有证据，才宣告迁移完成。文档、接口单测和包体积下降都不能单独替代这一结论。

## 10. 当前实施记录

- 用户后续要求直接删除内置副本，已移除 `packages/pet`、派生依赖和 patch 行、预构建登记及修改第三方文件的工具。发布集合变为主包加七个子包，共八个 tarball；不包含 pet 渲染器、Electron、基础素材或字体。
- 正式默认入口只使用官方协调器；不再提供内置或 `official-preview` 开关。客户端在 Cordis 生命周期中读取同页 `petApi7340`，按明确 petId 执行动作。目标选择由本插件自己的浏览器存储保存，不改官方配置；其他调参为本页运行时覆盖，可导出 JSON。
- 四套侧栏、抓绳、踢腿弹飞和哈气排播已接到官方 anim、position、throw。五张自绘气泡具有独立出现/隐藏节点与偏移设置；动作解锁后仍可留存，不清理官方原生气泡。
- 专项夹具覆盖多目标、同目标两页面互斥、短租约、失锁、迟到响应、旧清理、四套排播、调参和卸载。真实本地 HTTP 验证限长请求、跨源拒绝、素材 Range；真实隔离 DSH 的八包安装与无官方 pet 启动已通过。它们不等于完整官方 React 宠物或桌面窗口的真机演出验收。
- 运动差异仍存在：对固定官方提交中真实 `applyPositionCue` 的隔离测试显示，视频在 250ms 缓冲后，直线运动仍按墙钟推进；100→400px、1000ms 的运动在墙钟 750ms 时到达 325px，而视频仍对应 175px，偏差 150px。当前桥接不承诺原始 4px / 80ms 视觉等价，不以每帧 HTTP、私有 DOM 接管或重新内置 pet 隐藏差异。
- 旧 profile 的派生 bundle、依赖和用户数据不会在启动时自动删除，外部补丁也不会自动恢复。升级前须关闭宿主并显式停用旧内置 bundle；不得误卸载官方包或删除个人数据。
- 完整官方安装上的四套演出、用户拖拽、视频缓冲和桌面同步效果仍需真机验收。本轮没有 npm 发布、远端提交推送或活动 profile 操作。
